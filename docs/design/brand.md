# Brief de nombre e identidad visual

Estado: propuesta creativa para revisión. El nombre de trabajo sigue siendo ¿Es estafa?; no se ha aprobado una marca definitiva.

La identidad debe transmitir calma, criterio y ayuda cercana. El usuario puede llegar preocupado; la interfaz debe darle información concreta y control de su siguiente paso.

## Nombre

El nombre debería pronunciarse y escribirse fácilmente en español, funcionar para mensajes y protección futura, y evitar prometer certeza o aparentar una afiliación bancaria.

| Candidato creativo | Ventaja | Aspecto a evaluar |
|---|---|---|
| ¿Es estafa? | Explica la pregunta inicial y permite lanzar con claridad | La respuesta del producto debe expresar incertidumbre |
| Ojo al mensaje | Cercano y relacionado con el momento de uso | Evaluar si sirve también para protección de dispositivos |
| Antes del clic | Invita a detenerse antes de actuar | Puede limitar la percepción a enlaces |

Son ideas para conversar, sin afirmar disponibilidad de marca, dominio ni identificadores. La selección definitiva requiere revisar esos usos. El nombre comercial, el nombre técnico del repositorio y el dominio son decisiones distintas.

## Dirección visual

Propuesta: fondos claros, texto oscuro, acento azul y tarjetas de evidencia legibles. Reservar rojo, ámbar y verde para estados, con etiqueta e icono. El verde comunica «sin señales detectadas» con su cobertura; no significa seguridad garantizada.

| Token propuesto | Color | Uso |
|---|---|---|
| background | `#F8FAFC` | Fondo general |
| surface | `#FFFFFF` | Entrada, resultados y paneles |
| text | `#0F172A` | Contenido principal |
| text-muted | `#475569` | Ayudas y metadatos |
| primary | `#1D4ED8` | Acción principal y enlaces |
| risk-high | `#B91C1C` | Riesgo alto, con etiqueta |
| risk-medium | `#92400E` | Precaución, con etiqueta |
| risk-low | `#166534` | Señales de menor riesgo, con explicación |
| border | `#CBD5E1` | Separación visual |

Tipografía inicial: sans del sistema para evitar dependencias de carga. Tamaño base de 16 px, párrafos cortos y dominios con tipografía monoespaciada. La paleta necesita comprobar contraste en las combinaciones reales del diseño.

Comprobación inicial: los seis colores de texto y estado superan 6:1 sobre los fondos blanco y `#F8FAFC`. Esto no valida por sí solo los estados de foco, bordes, componentes ni la accesibilidad de una pantalla terminada.

## Logo y componentes

Antes de un símbolo definitivo, basta un wordmark legible con el nombre de trabajo. Tras aprobar nombre y dirección visual se diseñan logo, versión monocroma, favicon y variante a 24 px. Un icono de banco, un sello oficial o un escudo con check pueden dar una promesa equivocada y requieren especial cuidado.

El primer sistema de UI debe definir botones, entrada de consulta, tarjeta de evaluación, evidencia con fuente, mensaje conversacional, cuota, fila de historial, aviso y estado vacío. Cada componente tendrá estados de foco, carga, error y deshabilitado.

## Orden de validación

1. Promesa y audiencia.
2. Nombre de trabajo y tono.
3. Flujos y wireframes.
4. Una pantalla representativa con la paleta propuesta.
5. Logo y ajustes del sistema visual.

El logo no bloquea la especificación de negocio ni el contrato de la API.
